# 강화학습 과정 (route_C, 온라인 Double DQN)

C가 배우는 과정을 `rl/train_rl.py` 기준으로 정리함. 기본 설정은 7차 테스트 기준 (`rl/학습안정화_기록.md`).

## 1. 큰 흐름: 에피소드 반복 + 검증 평가

```
검증 0 (학습 전) → 에피소드 1 (severe, 시드 1001) → 에피소드 2 (high, 1002) → …
→ 에피소드 5 → 검증 1 → … → 에피소드 80 → 검증 16
```

- 에피소드 하나 = 10초짜리 시뮬레이션 한 번. 주 흐름 4개 (흐름마다 초당 60개), 결정 약 3만~3만 5천 번
- 에피소드마다 혼잡 단계(high : severe = 1 : 2로 무작위), 배경 트래픽, 주 흐름의 출발지와 도착지(흐름 0 포함, 최소 지연 30~45 ms)가 바뀜
- 검증과 최종 평가에서는 흐름 0을 (0,0) → (5,5)로 고정 (학습 때 본 적 없는 가장 먼 경로)
- 흐름 4개의 결정이 모두 같은 신경망으로 라우팅되고, 모두 학습 경험으로 쓰임
- 신경망은 처음부터 끝까지 하나이며, 계속 고쳐 나감
- 학습 시작 전과 5 에피소드마다 학습을 멈추고, 검증 시드 501~503으로 ε 0 평가 (high, severe) → `eval_log.csv` (학습 곡선)
- 학습 시드(신경망 초기값)를 바꿔 여러 번 학습: `python rl/train_rl.py 80 0 0`, `… 0 1`, `… 0 2`
- 혼잡 단계 비율은 마지막 인자로 바꿈: `python rl/train_rl.py 80 0 0 1:1:2` (base : high : severe, 0이면 그 단계는 학습과 검증에서 뺌, 기본 0:1:2). `python run.py`로 학습하면 이 비율을 물어봄
- 지금까지는 시간 때문에 high, severe만 학습 (base 단계는 코드에 그대로 있음)

## 2. 에피소드 안에서 (1 ms마다)

패킷이 위성에 도착할 때마다 아래 과정을 거침.

### (1) 보기 (State 15개)
| 항목 | 값 | 개수 |
|---|---|---|
| 방향별 큐 상태 | 3단계: 여유 0 (100개 미만), 보통 0.5 (100~150개), 혼잡 1 (150개 이상) | 4 |
| 이웃 위성 부하 | 30 ms 전 값 ÷ 200 | 4 |
| 링크 유무 | 있음 1, 격자 끝 0 | 4 |
| 목적지까지 남은 거리 | ÷ 5 (반대쪽이면 음수) | 2 |
| 남은 기한 | ÷ 70 | 1 |

- 정확한 큐 길이 대신 대략적인 단계만, 이웃 정보는 오래된 값만 줘서 힌트를 줄임 (나머지는 보상으로 배움)
- 이전 실험의 State 24개 (`'full'`), 16개 (`'noTrend'`)는 `config_rl.py`의 `RL.stateMode`를 바꿔야 씀

### (2) 고르기 (Action)
- 상, 하, 좌, 우 중 하나. 링크가 없는 방향만 제외함 (행동 마스크, `maskMode='link'`)
- 꽉 찬 큐, 기한 안에 못 가는 방향은 막지 않고 손실 보상으로 직접 피하는 법을 배움 (예전 방식은 `maskMode='full'`)
- 확률 ε만큼 무작위로 고름 (탐험), 나머지는 Q값이 가장 큰 방향

### (3) 결과 받기 (Reward)
| 언제 | 보상 |
|---|---|
| 매 홉 | −링크 지연 ÷ 70 (큐 항목 없음, `RL.rewardHopQueue = False`) |
| 기한 내 도착 (끝) | +0.5 |
| 단발 손실 (1~2개) | −0.1 |
| 연속 손실 (3개 이상) | k번째 패킷 −min(1.0, 0.2 + 0.1 x max(0, k − 3)) → −0.2 ~ −1.0 |

- 연속 손실 여부는 앞뒤 패킷 결과를 기다렸다가 정함 (`rl_collector.py`)
- 연속 손실이면 처음 2개를 포함한 구간 전체가 연속 손실 보상을 받음
- 상한(−1.0)을 두어 드문 대형 손실이 학습 전체를 흔들지 않게 함

### (4) 경험 저장
- (본 것, 고른 방향, 받은 보상, 다음 위성에서 본 것)을 경험 하나로 만들어 리플레이 버퍼에 넣음 (최대 100만 개)
- 위성들의 경험이 모두 한 버퍼에 모임 (중앙 학습, CTDE)

### (5) 배우기
- 경험 20만 개(흐름 하나당 5만, 에피소드 약 6)가 쌓인 뒤부터, 결정 16번(흐름 하나당 4번)마다 한 번 버퍼에서 64개를 무작위로 꺼내 학습
  → 에피소드당 학습 횟수가 흐름 1개 때와 같음
- 목표값 = 받은 보상 + 0.95 x (다음 상태에서 앞으로 받을 점수)
- Double DQN: 다음 상태의 최고 방향은 학습 신경망이 고르고, 그 점수는 타깃 신경망이 매김
- 학습률 0.0001 (Adam), Huber 손실, 기울기 최대 10
- 학습 2,500번(에피소드 약 1.1개)마다 타깃 신경망을 통째로 복사 (hard update)
  - soft update (`RL.tau` > 0)는 가치가 빨리 퍼져 학습이 너무 빨리 시작됨 (6차). 기본은 끔

## 3. 학습 진행에 따른 변화

| 시점 | ε (무작위 비율) | 모습 |
|---|---|---|
| 처음 (약 1~6 에피소드) | 1.0 → 약 0.55 | 경험만 모음 (20만 개 쌓일 때까지 학습 안 함) |
| 탐험 구간 (약 13 에피소드까지) | → 0.05 | 무작위를 줄이며 배운 것을 점점 많이 씀 |
| 이후 (약 13~80 에피소드) | 0.05 | 스스로 배우며 성능이 오름 (7차: ε이 끝나고 에피소드 13~28개 뒤에 오르기 시작) |

- ε은 결정 40만 번(흐름 하나당 10만)에 걸쳐 1.0에서 0.05로 줄어듦
- 학습 중 성능에는 ε 무작위가 섞여 있어서, 실제 실력은 검증 평가(ε 0)로 봄

## 4. 학습 목표와 판정

학습이 끝나면 `python analysis/learning_targets.py 학습폴더 [학습폴더 ...]`로 판정.

| 목표 | 기준 |
|---|---|
| 학습 진행 | 최종 도착률이 시작보다 5%p 이상 상승 |
| T50, T90 | 오른 폭의 50%가 전체 학습의 20% 이후, 90%가 40~70% 사이 |
| 평가 점, 급상승 | 25개 이상, 연속한 두 점 사이 15%p 이하 |
| 수렴 | 최근 평가 3번 도착률 차이 2%p 이내, 연속 손실 ±20% 이내, 학습 손실이 커지지 않음, 전체의 75% 이전 |
| 안정성 | 수렴 뒤 하락 5%p 이하, 발산 없음, 학습 시드 간 표준편차 3%p 이하 |

## 6. 학습이 끝난 뒤 (최종 평가)

- 학습 시드별 모델을 한 번에 평가: `python eval_routes.py 모델0,모델1,모델2` (기본 high, severe, B와 C)
- ε 0, 신경망 고정, 학습 때 쓰지 않은 평가 시드에서 B(DRA)와 같은 조건으로 비교 (A는 `routeA,routeB,routeC`로 고를 때만)
- 흐름 0 지표는 `per_seed.csv`의 `mainOnTimeRate`, `mainMaxConsecLoss`
- 판정: `python analysis/compare_runs.py 평가폴더` → B 대비 연속 손실 감소, 도착률, 지연, 짝지은 승률, 95% 신뢰구간
