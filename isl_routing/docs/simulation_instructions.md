# 시뮬레이션 설명

이 시뮬레이션이 무엇을 하고, 한 번 돌리면 어떤 결과가 나오는지 정리한 문서.

## 1. 시뮬레이션이 하는 일

실시간 UDP 흐름 4개가 같은 위성망을 함께 쓰는 상황에서, 라우팅이 혼잡을 얼마나 잘 피해 **기한 안에, 연속 손실 없이** 도착시키는지 측정함. 결과 숫자는 측정 흐름(흐름 0, 우리 GSL) 기준.

| 항목 | 값 |
| --- | --- |
| 시간 단위 | 1 step = 1 ms |
| 에피소드 | 10초 (10,000 step), 큐가 빈 상태로 시작 |
| 망 | 끝이 막힌 직사각형 가상 격자 (6x6 기본, 크기 지정, Iridium 크기 6x11, Starlink 크기 72x22). 원형 연결, seam, 극지방 없음 (11/26 회의) |
| 링크 | 상/하 지연 7 step, 좌/우 지연 2 step, 1 step에 5개 전송, 링크별 큐 200개 |
| 주 흐름 | 4개, 흐름마다 초당 60개, 160 Byte (아래 표) |
| 기한, TTL | 흐름마다 그 흐름의 최소 지연 + 25 ms, 최소 홉 + 10 (6x6 (0,0) → (5,5)는 70 ms, 20홉) |
| 배경 트래픽 | 모든 링크에 기본 부하 (용량의 0.1~0.4배) + 지역 핫스팟이 무작위로 생겼다 사라짐 (평균 1초) |
| 혼잡 단계 | base, high, severe (6x6 기준 핫스팟 발생 간격 평균 1초, 0.5초, 0.25초, 동시에 걸린 지역 약 1, 2, 4개). 위성 수에 비례해 더 자주 |

주 흐름 (`sim/flows.py`, 에피소드 시드로 정하고 에피소드 동안 고정)

| 흐름 | 시험 (검증, 최종 평가) | 학습, 적응 |
| --- | --- | --- |
| 흐름 0 = 측정 흐름 (우리 GSL) | (0,0) → 격자 맨 끝 모서리 고정 (6x6은 (5,5), 최소 지연 45 ms) | 시험 측정 흐름 최소 지연의 90% 이상인 쌍 중 무작위 |
| 흐름 1~3 = 다른 GSL 흐름 | 가장 먼 거리의 25~100%를 세 구간으로 나눠 짧은, 중간, 먼 흐름이 고르게 섞인 무작위 쌍 | 같음 |

- 성능 지표는 측정 흐름 기준. 다른 GSL 흐름은 트래픽 역할이고 흐름별 결과(`flow_analysis`)에서만 봄
- 다른 GSL 흐름은 홉 수가 측정 흐름 이하이고, 기한 여유가 측정 흐름과 같거나 더 넉넉한 쌍만 씀
- 같은 시드면 B와 C가 같은 흐름, 같은 배경 트래픽으로 비교됨
- 흐름끼리 출발 위성, 도착 위성이 겹치지 않음
- 꽉 찬 큐(200개)를 한 번 지나면 약 40 ms를 기다려서 짧은 흐름은 거의 기한 초과
- 에피소드 e는 시작 시드 + e를 씀
- 시드: 최종 평가 1~20, 학습 중 검증 501~503, 학습 1001부터, 적응 2001부터

## 2. 매 step(1 ms)마다 반복하는 순서

1. **도착:** 링크를 건너온 패킷의 홉 +1, TTL −1
2. **목적지 확인:** 자기 흐름의 도착 위성이면 그 흐름의 기한 안/밖을 판정하고 끝
3. **중간 확인:** 기한이 지났거나 TTL이 0이면 손실
4. **생성:** 주 흐름 패킷과 배경 패킷 생성 (배경은 XY 고정 경로로 먼저 큐에 넣음)
5. **라우팅:** 주 흐름 패킷마다 route_A, route_B, route_C 중 하나가 다음 방향을 고름. 큐가 꽉 찼으면 오버플로 손실
6. **전송:** 링크마다 큐 앞에서 최대 5개를 보냄
7. **기록:** 링크별 최근 큐 길이와 넘침 시각 (C의 관측용), 노드 기록

## 3. 실행 종류별 결과

| 실행 | 하는 일 | 결과 |
| --- | --- | --- |
| `main_isl.py` | 고른 라우팅(기본 B)을 ε 0으로, 데이터 수집용 B를 ε 0.1로 같은 배경 트래픽에서 실행 | `metrics_summary`, `packet_log`, `burst_log`, `decision_log` (ε 0.1), `node_log`, `bg_scenario`, 그래프, 애니메이션 (ε 0) |
| `rl/train_rl.py` | C를 학습 격자(기본 10x10)에서 80 에피소드 학습, 5 에피소드마다 검증 평가 | `train_log`, `eval_log`, 모델 파일 |
| `rl/adapt_rl.py` | 학습한 C를 평가할 격자에서 5 에피소드 짧게 추가 학습 (적응 전, 뒤 검증 평가) | `train_log`, `eval_log`, 적응한 모델 |
| `eval_routes.py` | 평가 시드 1~20에서 B, C(학습 시드별) 비교 (A는 고를 때만), 측정 흐름 기준 | `summary`, `per_seed` (막대 그림은 `viz/plot_eval.py`) |

## 4. 연속 손실의 정의

- **손실:** 기한 안에 도착하지 못한 모든 패킷 (목적지 기한 초과, 중간 기한 초과, 큐 오버플로, TTL 만료)
- **연속 손실:** 같은 흐름 안에서 패킷 번호(생성 순서) 순서로 손실이 `P.burstMinLen`개(3개) 이상 이어진 구간 1개 = 1번
- **단발 손실:** 1~2개만 이어진 손실
- 흐름, 에피소드 경계에서는 끊어서 셈 (서로 다른 흐름이나 시뮬레이션의 손실은 이어진 손실이 아님)

## 5. 시각화

- `python tools/show_results.py`: 표, 그래프, 노드 그림, 애니메이션 창
- `python tools/show_node.py p s`: 노드 (p,s)의 시간 변화
- `python viz/plot_rl.py 학습폴더 [평가summary.csv]`: 학습 곡선, 라우팅 비교 그래프
- `python viz/plot_compare_tests.py "이름=학습폴더" ...`: 테스트(학습 설정)별 학습 곡선 비교
- `python viz/plot_eval.py 평가폴더`: 최종 평가 막대 비교
- `python viz/plot_flows.py 결과폴더`: 흐름별 결과 (시뮬레이션 뒤 자동 실행)
