# 시뮬레이션 설명

이 시뮬레이션이 무엇을 하고, 한 번 돌리면 어떤 결과가 나오는지 정리한 문서.

## 1. 시뮬레이션이 하는 일

출발 위성 (0,0)이 도착 위성 (5,5)로 패킷을 보내고, 라우팅이 혼잡을 얼마나 잘 피해 **기한 안에, 연속 손실 없이** 도착시키는지 측정함.

| 항목 | 값 |
| --- | --- |
| 시간 단위 | 1 step = 1 ms |
| 에피소드 | 10초 (10,000 step), 큐가 빈 상태로 시작 |
| 주 흐름 | 초당 60개, 160 Byte, 기한 70 ms, TTL 20홉 |
| 링크 (6x6) | 상/하 지연 7 step, 좌/우 지연 2 step, 1 step에 5개 전송, 링크별 큐 200개 |
| 배경 트래픽 | 모든 링크에 기본 부하 (용량의 0.1~0.4배) + 지역 핫스팟이 무작위로 생겼다 사라짐 (평균 2.5초) |
| 혼잡 단계 | base, high, severe (핫스팟 발생 간격 평균 2.5초, 1.25초, 0.625초) |
| 망 구조 | 6x6 격자 (기본), 크기 지정 격자, Iridium, Starlink |

- 최단 경로로 가면 45 ms (좌우 5홉 x 2 + 상하 5홉 x 7), 기한까지 여유 25 ms
- 꽉 찬 큐(200개)를 한 번 지나면 약 40 ms를 기다려서 거의 기한 초과
- 에피소드 e는 시작 시드 + e를 씀. 같은 시드면 같은 배경 트래픽
- 시드: 최종 평가 1~20, 학습 중 검증 501~505, 학습 1001부터

## 2. 매 step(1 ms)마다 반복하는 순서

1. **도착:** 링크를 건너온 패킷의 홉 +1, TTL −1
2. **목적지 확인:** 도착 위성이면 기한 안/밖을 판정하고 끝
3. **중간 확인:** 기한이 지났거나 TTL이 0이면 손실
4. **생성:** 주 흐름 패킷과 배경 패킷 생성 (배경은 XY 고정 경로로 먼저 큐에 넣음)
5. **라우팅:** 주 흐름 패킷마다 route_A, route_B, route_C 중 하나가 다음 방향을 고름. 큐가 꽉 찼으면 오버플로 손실
6. **전송:** 링크마다 큐 앞에서 최대 5개를 보냄
7. **기록:** 링크별 최근 큐 길이와 넘침 시각 (C의 관측용), 노드 기록

## 3. 실행 종류별 결과

| 실행 | 하는 일 | 결과 |

| `rl/train_rl.py` | C를 270 에피소드 학습, 10 에피소드마다 검증 평가 | `train_log`, `eval_log`, 모델 파일 |

## 4. 연속 손실의 정의

- **손실:** 기한 안에 도착하지 못한 모든 패킷 (목적지 기한 초과, 중간 기한 초과, 큐 오버플로, TTL 만료)
- **연속 손실:** 패킷 번호(생성 순서) 순서로 손실이 `P.burstMinLen`개(3개) 이상 이어진 구간 1개 = 1번
- **단발 손실:** 1~2개만 이어진 손실
- 에피소드 경계에서는 끊어서 셈 (서로 다른 시뮬레이션이라 이어진 손실이 아님)
